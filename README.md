# 快递驿站智能管理系统

纯 C 语言实现（C99），控制台伪图形界面，无需任何第三方库。

![Language](https://img.shields.io/badge/language-C99-blue)
![Platform](https://img.shields.io/badge/platform-Windows-lightgrey)
![License](https://img.shields.io/badge/license-MIT-green)
![Lines](https://img.shields.io/badge/lines-~1984-brightgreen)

> 数据结构课程设计项目。用 djb2 哈希表 + 拉链法实现取件码索引，配一张 6×20 的货架二维位图，
> 做成一个能真正跑起来的驿站业务系统：双角色权限、分类分区存放、超期保管费、运营报表、数据持久化。


## 项目一览

| 项目 | 说明 |
|---|---|
| **语言** | C99（纯 C，无第三方库） |
| **规模** | 15 个 `.c`，约 1984 行（连 `station.h` 约 2214 行） |
| **核心结构** | 哈希表（djb2 + 拉链法）、单链表、6×20 二维位图、指针数组 + `qsort` |
| **界面** | 控制台伪图形（边框 / 颜色 / 中文对齐表格），三个角色界面 |
| **持久化** | 文本文件存放，重启自动恢复；文件头设计为向后兼容 |
| **构建** | Dev-C++ / MinGW-w64 gcc / VS 2022 MSVC / VS Code 均可 |

**核心功能**

- **双角色模式** —— 取件模式只开放「取件 / 尾号查询」，管理员口令进入后台
- **分类分区存放** —— 六排货架切成 5 个区（普通 / 易碎 / 电子 / 液体 / 生鲜），入库自动入区，满则降级
- **超期保管费** —— 免费 48 小时，之后阶梯计费，取件时结算、报表汇总
- **货物清单** —— 全部在库货物按入库时间排序，滞留件标红，带在库时长与保管费
- **运营报表** —— 业务量 / 周转 / 分区占用 / 营收 四个视角
- **哈希性能实验** —— 实测哈希查找与顺序查找的比较次数差距

## 二、文件结构

```
├── station.h        公共头文件：常量、结构体、全部函数声明（先看这个）
├── hash.c           哈希表核心：djb2 散列、查找、插入、删除、货架分配（含分区）
├── util.c           小工具：时间格式化、手机号脱敏、取件码生成、分类映射、跨天清零
├── fee.c            超期保管费：超期天数、阶梯计费、全站应收合计
├── ui.c             界面：颜色、三套菜单、凭条、中文对齐、安全输入、口令输入
├── table.c          表格绘制：表头 / 数据行（含在库时长与保管费）/ 表尾
├── store.c          持久化：packages.dat 存取（文件头 v2 兼容旧格式）
├── log.c            操作日志：写日志 / 查看日志
├── inbound.c        [管理员 1] 快递员入库（选择类别 -> 分区落位）
├── outbound.c       [两个模式都能用] 用户取件出库（核验尾号 + 结算超期费）
├── query.c          [两个模式都能用] 手机尾号查询
├── goodslist.c      [管理员 4] 货物清单（全部在库货物，滞留标红，含保管费）
├── report.c         [管理员 5] 运营报表
├── experiment.c     [管理员 6] 哈希性能实验
├── demo.c           批量录入（一键生成示例包裹，便于演示与自测）
├── main.c           程序入口 + 双层主循环（身份分发）
├── 启动.bat         一键启动（缺 main.exe 时会自动编译）
└── .vscode/         VS Code 编译配置（不用 VS Code 可忽略）
```

共 **15 个 `.c`**，约 1984 行 C 代码（连 `station.h` 一起约 2214 行）。

**阅读顺序建议**：`station.h` → `hash.c` → `util.c` / `fee.c` / `ui.c` / `table.c`
→ `store.c` / `log.c` → 各业务模块（inbound / outbound / query / goodslist / report）
→ `experiment.c` / `demo.c` → `main.c`。

每个 `.c` 文件开头都有「职责 / 依赖 / 被依赖」注释，顺着依赖链读不会卡住。

### 全局对象 gSt —— 全系统唯一的一份数据

数据不是层层传参，而是放在一个全局对象里（`station.h` 中 `extern Station gSt;`，
定义在 `main.c`）。所有函数都直接读写它，所以调用时不用传参数：

```c
/* 旧写法 */                        /* 现在 */
doPickup(&st);                       doPickup();
hashFind(&st, code, &cmp);           hashFind(code, &cmp);
st->count                            gSt.count
```

好处是想改数据结构时最省事：v2.0 往 `Station` 里加了「今日入库 / 今日出库 / 日期戳」
三个字段，只改了结构体和用到它的函数，没有一路去改调用点的参数。

唯一的例外是 `experiment.c` 的性能实验——它需要一张独立的临时表，
做法是先把 `gSt` 整体备份到局部变量、清空 `gSt` 当实验台，做完再整体还原。

## 四、重要：文件编码（务必注意！）

**所有源文件都是 UTF-8 with BOM 编码，请不要用编辑器改成「UTF-8 无 BOM」或「GBK」。**

原因：源码里有大量中文字符串。MSVC 在默认代码页（简体中文 Windows 为 936/GBK）下读
UTF-8 无 BOM 文件会解码错误——某些汉字的第二个字节恰好是 `0x5C`（反斜杠 `\`），
会把字符串的结束引号转义掉，导致字符串跨行，引发一连串报错：

```
error C2001: 常量中有换行符
error C2017: 非法的转义序列
error C4819: 该文件包含不能在当前代码页(936)中表示的字符
```

保留 BOM（或在编译参数里加 `/utf-8`）即可避免。gcc / clang 对带 BOM 的 UTF-8 同样兼容。

## 五、界面沉浸感：一行宏切换两种姿态

程序里有一个总开关 `SHOW_TECH_DETAIL`（在 `station.h` 顶部），
决定"要不要让使用者看到课程设计的技术痕迹"：

| 位置 | `0` 沉浸模式（默认） | `1` 展示模式 |
|---|---|---|
| 取件成功后的哈希比较次数 | 不显示 | 多一行「（哈希查找比较 1 次）」 |
| 取件失败提示 | 只说"取件码无效或包裹已取走" | 附带「本次比较 N 次」 |
| 运营报表末尾 | 到 `[ 营收 ]` 为止 | 多一段 `[ 哈希表 ]`（桶数、非空桶、最长链、装填因子） |
| 管理员登录页 | 不提示口令位置 | 打印「口令写在 station.h 的 ADMIN_PASS 里，默认 8888」 |

界面文案本身两种模式共用，都已经改成业务口吻：

- 不再出现 `packages.dat` / `station.log` 这类内部文件名
- 「生成演示数据」→「**批量录入**」，「滞留判定线」→「超过 N 小时未取即计滞留」
- 启动提示改为「首次启动，是否载入一批示例包裹以便熟悉系统?」
- 首屏多一行实时状态（在站件数 / 累计出入库），像真在运转的后台

一句话：**默认给用户看的是"系统"，答辩需要自证算法时切到"展示模式"。**

切换方式二选一：

```c
/* 方式一：改 station.h 顶部一行 */
#define SHOW_TECH_DETAIL  1
```

```bash
# 方式二：不动源码，编译时覆盖（推荐 —— 不用改回来）
gcc -std=c99 -O2 -Wall -Wextra -DSHOW_TECH_DETAIL=1 -o main_tech.exe *.c
```

> 答辩小技巧：平时用 `main.exe`（沉浸模式）演示业务流程，老师问"这真是哈希表吗"时，
> 直接运行 `main_tech.exe` 现场取件一次，那行"哈希查找比较 1 次"比任何解释都管用。

| 编号 | 功能 | 编号 | 功能 |

### 取件码规则

取件码由**货架号 + 层数 + 入库日期 + 4 位随机数**拼成，固定 11 位：

```
   A   -   05   -   12    2222
   │        │        │      └── 4 位随机数：区分同一天、同一货架的多件包裹
   │        │        └───────── 入库日期：1~31，入库那天是几号
   │        └────────────────── 层数：01~20，到货架后看第几层
   └─────────────────────────── 货架号：A~F，6 排货架
```

举例：`A-05-122222` 表示「A 号货架、第 5 层、12 号入库」。

**这样设计的好处**：用户拿到短信里的码，不用再查任何东西，一眼就知道去哪个货架、第几层；
即使货架标签被挡住，也能靠码里的信息定位。而且因为**货架是按类别分区**的，
码里的 A~F 顺带还告诉工作人员"这是什么类别的件"——分类信息是免费搭车带上去的。

- 取件时**大小写都能输入**（输 `a-05-122222` 也能查到），因为系统会自动转成大写再查
- 取件码在 `allocShelf` 之后才生成——必须先定下货架，码里的货架号才和实际位置一致
- 若同一货架同一天出现重码，程序会自动重摇末 4 位随机数

### 分类分区规则

六排货架按包裹属性切成 5 个区：

| 分区 | 货架 | 格位数 | 适合放什么 |
|---|---|---|---|
| 普通件 | A、B 排 | 40 | 衣物、日用品等 |
| 易碎品 | C 排 | 20 | 玻璃、陶瓷、显示器 |
| 电子产品 | D 排 | 20 | 手机、电脑配件 |
| 液体 | E 排 | 20 | 饮料、洗护用品 |
| 生鲜冷链 | F 排 | 20 | 需要尽快取走的生鲜 |

- 入库时选类别 → 系统只在对应区里找空位
- **某一区放满时不会入库失败**：自动降级到其它区的空位，并提示工作人员
- 类别**没有单独存进数据文件**，因为"排"和"类别"一一对应，拿货架号就能反推
  （少存一列冗余数据，也就不会出现"类别字段和货架位置对不上"的不一致）

### 超期保管费规则

- **免费保管 48 小时**（和滞留判定同一个口径）
- 超出后：前 **2 天 1 元/天**，第 3 天起 **2 元/天**，**不足一天按一天计**
- 取件时算出应缴金额、当面提示并打印在凭条上；管理员报表里汇总"应收保管费"
- **费率怎么改**：`station.h` 顶部四行宏 —— `FREE_HOURS` / `FEE_DAY1` / `FEE_DAY2` / `TIER1_DAYS`

### 保存退出后，如何再次启动

数据是存在 `packages.dat` 里的，**关掉程序不会清空数据**，重新启动就会自动恢复上次的现场。
三种方式任选其一：

| 方式 | 操作 | 说明 |
|------|------|------|
| **双击启动器**（推荐） | 双击 `启动.bat` | 自动切换到程序目录；万一 `main.exe` 没了还会自动编译 |
| **VS Code** | `F5`，或 `Ctrl+Shift+B` 后运行 | `F5` 会先自动编译再启动 |
| **直接运行** | 双击 `main.exe` | 最简单，但要求 `main.exe` 与 `packages.dat` 在同一个文件夹 |

重新启动后，第一屏会显示：

```
今日营业中：在站 30 件，累计入库 30 件 / 出库 0 件。
```

看到这行就说明上次的数据完整恢复了。

> **注意：不要把 `main.exe` 单独拷到别的文件夹去运行。** 数据文件是按"当前工作目录"找的，
> 换目录等于换了个新系统，会提示"未找到数据文件"。

### 数据安全

- **入库 / 取件后会立即写盘**，所以即使直接点窗口右上角的 `×` 关掉，数据也不会丢

## 七、核心考点速览（答辩用）

| 考点 | 位置 | 说明 |
|------|------|------|
| 哈希函数 djb2 | `hash.c` `hashIndex()` | 初值 5381、乘数 33（= 2⁵+1，可用移位实现） |
| **为什么不能 atoi 取模** | `hash.c` | 取件码以字母开头（`A-05-122222`），`atoi` 遇到 `'A'` 直接返回 0，所有包裹会全挤进 0 号桶、哈希表退化成一条链表。djb2 逐字符运算才能打散 |
| 冲突处理·拉链法 | `hash.c` | 同桶用单链表串接，`Package.next` 指针 |
| 链表删除 | `hash.c` `hashRemove()` | 分「删头节点」「删中间节点」两种情况 |
| **装填因子** | `report.c` | **在站件数 ÷ 桶数**（30 ÷ 1013 ≈ 0.03）；非空桶数另外单独打印，两个数一起看能判断散列质量。**默认沉浸模式下不显示**，要现场展示时用 `-DSHOW_TECH_DETAIL=1` 编译 |
| **界面与技术分离** | `station.h` `SHOW_TECH_DETAIL` | 同一份业务代码，靠一个宏决定"面向用户"还是"面向答辩"；技术指标的可见性是一行宏，不散落在各处 |
| 性能对比实验 | `experiment.c` | 实测哈希 O(1) 与顺序查找 O(n) 的差距 |
| 数据持久化 | `store.c` | 分行文本存储，启动时逐条读回并重建哈希表与货架占用表 |
| **文件格式向后兼容** | `store.c` `loadData()` | 头行从 2 字段扩到 5 字段（新增今日计数与日期戳），按"读几个算几个"处理，旧数据文件拿来就能用，不用转换 |
| 排序 + 函数指针 | `goodslist.c` | 哈希表天然无序，要按入库时间输出必须先把节点指针收进数组，再用 `qsort` + 自定义比较函数排序（比较函数收到的是 `void*`，要转成 `Package**` 再解引用） |
| **二维数组做位图** | `hash.c` / `Station.shelf` | 货架占用用 `int shelf[6][20]`，一个格子 0/1 表示空/占用；满载时入库明确失败 |
| **分类分区分配** | `hash.c` `allocShelfByCat()` | 类别 → 排区间的映射（`catRowFrom/To`），在本区内找空位，满了自动降级到其它区 |
| **业务规则与代码分离** | `fee.c` + `station.h` | 费率全写成宏（`FEE_DAY1` 等），改规则只动头文件四行，不用在 ui / table / report 里到处找 |
| **权限做在界面层** | `main.c` | 两个角色共用同一批业务函数，差异只在"菜单放出了哪几项"——加角色不用改业务逻辑 |
| 全局状态设计 | `station.h` / `main.c` | 整个系统一份 `gSt`，函数不再传表指针；代价是 `experiment.c` 必须自己做备份—还原 |
| 编码方案设计 | `util.c` `genCode()` | 取件码把「货架-层数-日期」编进字符串，是空间换查询的典型思路 |

## 八、常见问题

**Q：进入管理员模式时提示"口令错误"，进不去？**
A：默认口令是 `8888`（写在 `station.h` 的 `ADMIN_PASS` 里）。连续输错 3 次会被锁定并退回
身份选择。演示前如果嫌麻烦，可以把那一行临时改成更简单的口令。

**Q：某个区放满了还能入库吗？**
A：能。系统会自动降级到其它区的空位，并在入库后提示工作人员"该区已满，已就近安排"。
只有整座货架 120 格全满时才会入库失败。

**Q：保存退出后重新启动，提示"首次启动，是否载入一批示例包裹以便熟悉系统? "**
A：两种可能：
1. 真的没有数据（第一次运行）——输入 `y` 载入示例包裹即可；
2. 程序的工作目录不对——`packages.dat` 是按"当前目录"找的，如果 `main.exe` 被单独搬到别处，
   它就在那个新的空目录里找，自然找不到。用 `启动.bat` 启动（它会 `cd` 到脚本所在目录），
   或者确认 `main.exe` 和 `packages.dat` 在同一个文件夹。

**Q：包裹全部取完之后重启，为什么也提示"未找到数据文件"？**
A：这是已修掉的老问题（`loadData` 把"文件不存在"和"在站件数为 0"混为一谈了）。
现在这种情况会正确显示 `今日营业中：在站 0 件，累计入库 x 件 / 出库 y 件`，
累计入库/出库的次数不会丢。

**Q：升级到 v2.0 后，v1.0 生成的 `packages.dat` 还能用吗？**
A：能。文件头从 2 字段扩到 5 字段，读取时"读几个算几个"——旧文件只读到 2 个字段，
今日计数就从 0 起算、日期戳补今天，包裹数据一件不丢；下一次保存会自动写成新格式。

**Q：取件码里的货架号和包裹实际货架不一致？**
A：不会。生成顺序是「先 `allocShelf` 分配货架 → 再 `genCode` 按该货架生成码」，
两者必然一致。如果手动改了 `packages.dat` 里的货架字段，那码里的货架号就只是历史记录了。

**Q：编译报 `LNK1168: 无法打开 main.exe 进行写入`**
A：程序还在运行，Windows 锁住了 exe。先关掉程序窗口再编译。
（用 VS Code 按 `Ctrl+Shift+B` 会自动先结束旧进程，不会遇到这个问题）

**Q：运行后中文是乱码**
A：确认源文件的 UTF-8 BOM 没被编辑器去掉；程序内部已调用 `SetConsoleOutputCP(65001)`，
并在退出前用 `uiCleanup()` 还原成原来的代码页，不会影响外面的命令行窗口。

**Q：表格边框对不齐**
A：说明源文件编码被改了，中文的显示宽度计算（中文占 2 列）失效了。

**Q：能改成 C++ 吗？**
A：可以，把 `.c` 改成 `.cpp` 即可编译。但代码本身是纯 C 风格（结构体 + 指针 + 函数），
不涉及类，保持 `.c` 更符合课程要求。
